# Aurora OS M4.5.1 — display resolution control

- Sets the Limine boot-time framebuffer request to **1280 x 720 x 32-bit** by default. Limine will select a fallback framebuffer mode if this exact mode is not available from the boot environment.
- Adds a System > Resolution selector for **1280 x 720**, **1366 x 768**, **1600 x 720**, **1823 x 918**, and **1920 x 1080**.
- Adds live mode switching through the Bochs/QEMU VBE DISPI interface where the virtual VGA adapter supports it, including 32-bit linear-framebuffer mode, pitch readback, VRAM-capacity checks, and restoration of the previous mode when a request is rejected.
- Makes framebuffer renderer buffers resize-safe: allocate replacement buffers before freeing current ones, and regenerate the desktop wallpaper on a successful mode change.
- Recalculates taskbar/work-area geometry, clamps open windows, and resets mouse bounds after a successful switch.
- Updates the Settings default page and version labels to M4.5.1.

## Compatibility notes

- The default 1280 x 720 mode is requested at boot via Limine's `resolution: 1280x720x32` option. Limine automatically picks another mode if unavailable.
- Live switching is currently implemented for Bochs/QEMU-compatible BGA adapters. Firmware/VM display adapters that do not expose this interface will show an unsupported message in Settings and remain at their current resolution.
- A live mode selection applies immediately but is not persisted after reboot; the default boot mode remains 1280 x 720.
- This source build compiles and the ISO structure is checked, but a graphical VM boot could not be executed in this environment.


## Resolution-change crash hotfix
- Boot requests a 1920x1080 framebuffer mapping to reserve enough mapped scanout memory for all supported modes.
- Aurora switches to 1280x720 before the first console frame on Bochs/QEMU-compatible adapters.
- Runtime mode switching now validates requested and actual pitch*height against the originally mapped framebuffer capacity before presenting pixels.
- If the adapter rejects a mode or the mapped aperture is too small, the request is refused before accessing unmapped VRAM.
