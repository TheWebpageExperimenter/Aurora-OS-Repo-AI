# Aurora OS 5.1.0.02 — Kernel integrity, security API, browser fallback

## Implemented
- Added versioned Security API v1 with a fixed 64-record audit ring, severity counters, snapshots, and invariant checks.
- Added a runtime fingerprint of the kernel text section and a comparison API. This is a diagnostic self-check only; it is not a cryptographic signature, measured boot, or a tamper-proof trust anchor.
- Audits malformed/unsupported browser URI attempts. The browser never executes URI schemes and does not send requests.
- Hardened URI parsing to bound reads before checking scheme delimiters and reject malformed HTTP(S) forms.
- Added browser layout fallback for very small windows and bounds checks for cached URL length to reduce blank/invalid rendering states.
- Added TLS API v1 as a fail-closed capability/status interface. Certificate verification always fails until real TLS, DER parsing, chain building, hostname/date validation, and a trusted CA store are implemented.
- Branded the Limine menu using configuration options; the Limine executable itself was not replaced or rewritten.

## Security and compatibility notes
- There is no standardized TLS 3.0. The current standardized protocol family is TLS 1.3 (with earlier versions in some environments). This release does not implement TLS 1.3, so HTTPS must not be advertised as secure or treated as working.
- The security monitor is kernel telemetry and diagnostic integrity checking, not endpoint protection capable of preventing arbitrary compromise.
- Audit storage is volatile, fixed-size, and overwrites old records; this implementation is not SMP-safe and does not provide cryptographic log authentication.
- Virtual NIC/display code remains discovery-only; native drivers and network transport are not implied.

## Verification
Build and ISO structure are checked during packaging. Runtime boot, browser interaction, and security response testing in QEMU/VirtualBox/VMware require separate VM testing.
