# Aurora OS 5.1.0.01 — Browser safety and virtual display compatibility

## Browser crash hardening
- Added bounded URI validation for the fixed-size browser address buffer.
- Accepts HTTP/HTTPS URLs and host/path text; rejects unsupported schemes (including `javascript:`, `file:`, and `data:`) without trying to interpret or execute them.
- Requires `http://` or `https://` when a scheme is supplied.
- Clips address-bar rendering to its field so long input cannot paint over adjacent controls.
- Displays an explicit safe error state. No request is sent because the network transport stack is not implemented yet.

## Virtual display API v1
- Added `kernel/display.h` and `kernel/display.c` with a stable, null-safe display information API.
- Detects common QEMU/Bochs VGA, VirtualBox VGA/VMSVGA, VMware SVGA, and VirtIO GPU PCI identifiers.
- Reports the boot framebuffer and renderer status in boot diagnostics and Aurora Monitor.
- Keeps the Limine-provided framebuffer and software renderer as the safe rendering path across virtual machines. Existing Bochs/QEMU DISPI resolution changes remain guarded by framebuffer-capacity checks.

## Important limitations
- PCI display detection is not a native graphics driver. VMware SVGA, VirtualBox VMSVGA, and VirtIO GPU command queues/2D acceleration are not implemented; hardware acceleration is reported as unavailable.
- The browser still cannot load live pages. Ethernet packet I/O, IPv4, DHCP, TCP, DNS, HTTP, TLS, and CA validation remain future work.
- ISO build and structural checks are performed; runtime boot testing in VirtualBox, VMware, and QEMU is not available in this environment.
